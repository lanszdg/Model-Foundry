# v0.4 执行、数据、训练与推理规格

本文规定已交付的专业工程路径、执行语义与验收方法。运行仍是单文件 HTML，没有 Python、Node、GPU 或外部 API 的安装要求。

## 1. 数据工程

Corpus Studio 可完成 JSONL 导入、记录编辑、Unicode/HTML 规范化、长度与重复广告过滤、邮箱/电话替换、精确及近似去重、评测污染检查。近似检查比较文档 shingles，通过候选索引缩小比较范围，处理报告保存重复对象与文档簇。

训练与验证按文档簇分开。每个已清洗版本保存父版本、记录、处理规则、内容摘要和训练/验证统计。正在运行的作业使用提交时的快照；后续数据变化不会改写历史作业。

Tokenizer 使用 Unicode BPE 与字节回退，保存实际词表、合并规则、特殊 Token 与资产摘要。Packing 生成 Token、下一位置标签、loss mask、样本分段和 `cu_seqlens`；padding 不参与监督。Inspector 可切换训练/验证分片，检查每个位置。

`/workspace/atlas/data-mixture.json` 冻结领域混合比例。数据读取器按比例选择训练记录，零权重领域不进入该采样池。导入范围为 5 MB、最多 5,000 条记录；工程资产规模与设备资源由世界状态管理。

## 2. 脚本执行

`train.py` 导入项目中的 `project/recipe.py`，传入 `forward_step_func`。默认函数遵循 Bridge 的“取 batch → 执行 model → 返回输出与 loss function”结构。

```python
from functools import partial
from megatron.bridge.training.losses import masked_token_loss
from foundry.config import load_recipe

def forward_step(state, data_iterator, model, return_schedule_plan=False):
    batch = next(data_iterator)
    output_tensor = model(batch["tokens"], labels=batch["labels"])
    return output_tensor, partial(masked_token_loss, batch["loss_mask"])
```

运行时先解析 AST，再执行项目模块、变量、函数、导入、条件、有限循环、算术、索引和调用。Tensor 的乘法、求和、均值与标量运算传递梯度；修改输出或 loss mask 会改变实际训练更新。

预检执行一个独立前向样本；训练使用提交时冻结的源文件。错误保留文件、行号、调用栈、Worker 和训练阶段。执行轨迹可在 Code 和实验页查看。

独立工程脚本可通过终端执行，读写同一份虚拟文件系统：

```bash
python scripts/inspect_data.py
```

支持 `json.loads/dumps`、`pathlib.Path.read_text/write_text`、`open().read/write` 和 `print`。运行环境采用有边界的 Python 语义及框架接口，存在执行预算；它不是完整 CPython，也不会从真实主机导入任意 Python 包。

## 3. 训练、调优与后训练

Atlas 的资源规格保持 70B、80 层、64 个注意力头、BF16 与多节点 H100。TP/PP/CP/DP、批次、序列长度、重计算和 optimizer offload 影响分配、显存、计算、通信与 I/O 估算。

浏览器中的模型行为状态采用可训练的条件 Token 分布。前向产生逐 Token 损失和梯度，Adam 保存一阶/二阶状态；学习率预热与衰减、梯度裁剪、权重衰减作用于更新。工程资源模型与这个行为状态共同表达训练操作的后果，不会在内存中展开 70B Transformer 张量。

SFT 读取可编辑的 user/assistant 样本，仅 assistant 部分参与监督。DPO 读取可编辑偏好对，冻结 reference policy，使用 completion 的序列 log-probability 差计算 sigmoid 偏好损失和梯度。

实验扫描支持 2—4 个学习率。每次运行绑定自己的代码、数据、配方、数据游标和随机状态；调度、训练/验证损失、吞吐与成本可以比较。检查点保存执行程序、模型行为、优化器、RNG 和数据读取位置。

## 4. 评测与模型产物

评测绑定指定完整检查点，逐条执行 `/workspace/atlas/evaluation.jsonl`。结果保存 prompt、reference、实际生成、关键词召回、字符 F1 和错误；验证 NLL/perplexity 从隔离分片计算。发布门槛由 `release-gates.json` 冻结，失败时阻止模型转换。

转换任务分为读取检查点、重分片映射、写入 Safetensors 描述与资产校验。I/O 使用当前生效存储带宽，并受容量、服务可达性和源分片校验影响。中断只留下 staging 记录；完整模型和 Tokenizer 校验通过后才登记版本。

注册版本保存模型配置、权重索引、八个输出分片描述、Tokenizer、训练血缘、评测与门槛。模型资产不可混用 Tokenizer。已加载进程使用自己的固定资产；新副本或候选版本加载时重新校验磁盘产物。

条件 Token 行为不具备真实通用大模型的全部语言能力；评测允许暴露低召回、过拟合和不连贯输出，不会按训练结束自动制造高分。验收脚本有一项显式调整的测试门槛，用来验证后续产物交付；这不代表推荐的发布质量标准。

## 5. 请求生命周期

API 请求经过 ACCEPTED、QUEUED、PREFILL、DECODING，再以 COMPLETED、CANCELLED、TIMED_OUT、FAILED 或 REJECTED 结束。每个请求保存确定的模型、检查点、资产摘要、Tokenizer、解码参数和事件轨迹。

输出按 Token 推进；temperature、top-p、seed、重复惩罚、输出上限与停止串作用于生成。TTFT、TPOT、总耗时和吞吐从请求事件汇总，压测失败来自实际拒绝、超时或副本错误。

每个副本拥有 GPU 分配、活动序列、KV 容量、16-Token 块租约、前缀缓存与调度预算。相同资产的相同前缀可以复用；不同版本的缓存隔离。LRU 不会回收被活动请求引用的缓存。KV 紧张时可抢占并重新计算；结束、取消和失败会释放租约。

```bash
curl http://atlas-api/v1/chat/completions -d '{"model":"atlas-70b-v1","messages":[{"role":"user","content":"解释梯度累积"}],"max_tokens":128}'
apictl list
apictl cancel chatcmpl-1
kubectl get pods
kubectl logs atlas-api
```

工程终端保持连接等待，完成后写出带 usage 和 finish_reason 的响应。

## 6. 扩容、灰度与恢复

每个副本占用同一资源台账中的八张 GPU。扩容经历加载和预热，活动副本清空后才允许缩容。控制面不可用时，管理操作失败；已经驻留显存的模型可继续推理。

候选版本先校验与预热，再接受指定比例流量。提升和回滚只改变新请求的路由；活动请求保留接收时绑定的版本。节点失效时，相关活动请求报告失败，副本在有空闲 GPU 的健康节点重新加载，并留下恢复日志。

## 7. 存档与验收

浏览器工程使用 IndexedDB 原子事务保存，兼容迁移旧版 localStorage。导入、重置与旧自动保存按代数隔离；保存按钮等待持久化完成。关闭期间不推进工程，恢复后续接任务、请求和产物状态。

```bash
node verify.mjs
node build.mjs
node preview.mjs --qa
```

验收工程可在 `/__qa/` 下载并从应用正常导入。开发预览页不进入发布 HTML。

自动验收覆盖数据去重/污染/隔离、脚本行号与文件读写、零梯度效果、Token 优化器、SFT/DPO、质量门槛、转换中断重试、缓存、KV 资源不变量、取消/超时/过载、灰度/回滚、驻留服务与副本恢复，并回归 v0.2/v0.3 的设备和调度流程。
