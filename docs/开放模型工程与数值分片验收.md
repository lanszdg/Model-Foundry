## 从选择模型到交付

入口 → 选择开放模型，或工位 → 模型工程。按领域筛选后创建工程，会在共享虚拟文件系统中生成：

```text
/projects/project-N/
  dataset.jsonl       # 有类型、有 ID、有 train/validation 的数据
  recipe.json         # 精度、GPU、训练步数、学习率和各阶段覆盖配方
  stack.json          # 官方来源、环境依赖、数据格式与实现范围
  environment.lock    # 本项目环境准备记录
  data-manifest.json  # 数据数量、划分和内容摘要
  artifacts/run-N.json
```

运行环境是浏览器世界内的状态，不会在用户电脑执行 pip、下载大模型参数或安装驱动。创建项目后，需要先建设机房网络、存储、GPU 运行时和调度服务，再准备项目环境。

项目和已有 Atlas 训练、API 副本占用同一批物理 GPU 槽位。BMC、终端、调度器和监控读取同一份资源状态。资源不足进入等待；错误主机、断网、不可达存储、GPU/主机内存超限有对应失败原因。

每次运行冻结输入数据、配方、环境描述和父版本。编辑项目文件影响后续提交；取消不会发布半成品。恢复保留本次运行的参数、优化器、RNG 和步数。完整提交的产物记录父版本、数据摘要、参考参数和评测结果。

## 不同领域使用不同流程

| 工程 | 阶段 | 数据和执行目标 |
|---|---|---|
| 语言 | 数据 → 继续预训练 → SFT → DPO → 评测 → 导出 → 推理 | 文本、messages、偏好对；decoder 交叉熵、completion 监督和冻结参考偏好梯度 |
| 多模态 | 图文视频配对 → 对齐 → SFT → 评测 → Processor 打包 → 推理 | RGB 数值、帧时间、说明文字；当前参考目标为视觉条件特征预测 |
| V-JEPA | 视频 → 潜表示预训练 → cooldown → 冻结评测 → 导出 → 预测 | 有顺序的帧和掩码概念；当前参考路径执行 stop-gradient EMA target 与未来特征回归 |
| Cosmos | 视频准备 → Generator SFT → 预测评测 → 打包 → 服务 | 视频条件和未来特征；当前参考路径执行 flow 的 x0 参数化 |
| GR00T | 轨迹标准化 → 动作 SFT → 闭环评测 → 策略打包 → Policy Server | RGB、机器人状态、目标和 7 维动作；动作 flow 参考目标与逐步环境反馈 |
| VLA-JEPA | 多视角轨迹 → 联合预训练 → 动作适配 → 闭环评测 → 导出 → 服务 | 动作目标与未来特征目标共同反向，worldLoss 控制权重 |

`recipe.json` 的 `stages` 可以覆盖某阶段的训练步数和学习率。决策模型的后续适配使用更低的学习率，避免直接重复预训练配方破坏已有策略。视频时间戳必须严格递增，RGB 维度和数值范围必须一致；机器人动作要求 7 个有限值，重复的文档/episode ID 会被拒绝。

## 资源底座

新领域项目从官方报告规模建立容量规划，区分目标权重、优化器状态、激活和 CPU offload。它是容量预算，不是这些原生模型所有张量的精确清单。发布权重含 FP8/FP4 的模型，在本轮参考训练中按解码后的 BF16 容量规划，不假装具有完整低比特训练支持。

大型 MoE 项目默认采用 32 卡和 CPU 状态卸载。现有 1 TiB 主机内存可能不足，用户需先排空作业，通过建议配置或硬件文件增加主机内存。显存、主机内存、共享卡号和环境前提都会实际限制运行。

## 逐 rank 数值计算

`rank-numerics.js` 在数值参考 Transformer 中分配本地权重矩阵，按列并行或行并行执行实际矩阵乘法，通过列收集或部分结果求和形成输出。反向计算使用各 rank 的本地输入与权重，产生局部参数梯度并合并输入梯度。

流水线跨层边界复制激活，反向将梯度传回；Context Parallel 对线性计算的 Token 行分片，按上下文分片收集 K/V 并将梯度散回。轨迹包含本地 shape、轴区间、元素数、内容摘要、通信和反向事件。

这是浏览器进程里的逻辑 rank 执行，没有真实 CUDA 设备或 NCCL 通信。它还没有把所有数值 kernel 与 1F1B 的每个时间线事件逐条对应；多机数值通信算法和性能校准也未全部完成。因此原 100 项清单中的逐 rank 场景仍保留“部分实现”。

旧 Atlas 工程可在 `/workspace/atlas/execution.json` 启用 `enabled: true`、`sharded: true`，设置 `dtype` 后重新检查并提交；旧存档保持原有数值协议。

## 混合精度

实现 FP32 转换、BF16 round-to-nearest-even、FP16 正常数/次正常数/溢出，矩阵计算按所选格式读写。Norm、softmax 等敏感运算保留较高精度；优化器使用 FP32 master weights 和 moments。

FP16 backward 使用 loss scaling。检测到溢出时，跳过该次参数与 Adam 更新并降低 scale；scale、跳步计数、master 和 moments 随运行状态保存。当前没有 FP8/FP4/TF32 计算，也没有宣称与任意 GPU kernel 的舍入顺序逐 bit 相同。

## 评测与推理

评测使用独立 validation 记录，保存逐样本预测和误差。机器人策略还执行 12 步反馈轨迹，当前默认末端距离门槛为 0.5，配方中可以设置更严格的 `maxRolloutDistance`。这是当前二维参考场景的距离门槛，不是工业机器人任务成功率。

评测产物没有通过门槛时，导出会失败。部署绑定对应的冻结参数；“服务与闭环”可以选择样本 ID 发送请求，得到动作、潜表示、视频特征或 Token 数值输出。更换未部署的项目文件不会偷偷更新已部署的参数。

## 软件界面与保留差距

本轮增加可筛选目录、分领域工程图、运行记录、文件编辑器、数据预览、逐卡张量和策略轨迹。运行时保留稳定的导航与按钮，更新指标区。它是统一工程工作区，尚未像素级复刻全部原生软件。

GLM 的 DSA/MLA、DeepSeek 的稀疏专家与 Engram、Qwen 的 Gated DeltaNet/视觉编码器、Cosmos 的 VAE/DiT、GR00T 与 VLA-JEPA 的全部大型骨干尚未按官方参数逐算子实现。语言参考使用有预算 decoder，其他领域使用可训练的小型数值参考目标。当前不能据此声称已完整训练或运行上述官方大模型。完整数据格式、包依赖、外部服务协议、真实机器人动力学也仍有缺口。

原有固定 100 项针对 Dense Atlas 的清单保持 49 项闭环；本轮的领域扩展单独验收，不把新增模型数量或测试数量换算成更高完成率。

## 复现

```bash
node verify.mjs
python verify-transformer-reference.py
node progress.mjs --write
node build.mjs
```

`verify-v9.cjs` 对照单体与不同分片布局的全部 logits/梯度，检查实际 FP16 梯度溢出、AMP 原子跳步与持久化，再对全部 7 个目录项目验证数据、阶段、评测门槛、资源、恢复、导出与推理。浏览器另验证模型创建、短训与实际请求；600 步策略的独立轨迹距离约 0.0619，通过当前门槛。另通过内联 Worker 验证启用 BF16 分片的 2 步 Atlas 训练、32 分片提交和零控制台错误。
