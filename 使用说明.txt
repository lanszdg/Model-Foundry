MODEL FOUNDRY v0.2.0

打开 dist/index.html 即可运行。HTML 内已包含全部样式、脚本和 3D 场景，无外部依赖。

现场：WASD 移动，按住鼠标拖动观察，靠近并面向设备按 E。靠近电脑后 Tab 坐下，Esc 离座。界面按钮标记现场位置，不会将玩家直接传送到远处。

完整工程顺序：
1. 到各机柜前，打开机柜门，在接线页将 PDU 接至 PSU、管理网接至 eth0，计算节点还需将 IB 光纤接至 ib0。支持拖线或先后点击两端。
2. 硬件页上电、部署系统。网络页填写不重复的 10.42.0.10—15 地址，网关 10.42.0.1，DNS 10.42.0.10。保存后 netplan apply，再安装运行时。
3. 在 storage-01 的服务页安装 storage → 启动 → 挂载 /data。在 control-01 安装并启动 slurm、data、tracking、kubernetes 和 monitor。也可在工位终端执行 labctl install <service> / systemctl start <service>。
4. 坐到工位，Corpus Studio 接入项目语料或导入 JSONL。执行清洗 DAG，查看逐条输入输出与过滤原因，再编码构建训练分片。
5. Code 中检查配置并提交预训练。右上角可切到 12× 时间，MLflow 查看阶段耗时、Worker 与指标。终端可独立并排打开。
6. 数据工作区准备后训练集。Code 载入 SFT 配方、检查并提交；完成后再进行 DPO。
7. 模型仓库评测候选检查点，转换权重并注册。
8. 推理工作台发布模型，等待 READY，再对话与压力测试。Grafana 数据源连接后才采集指标。

故障：运行时可拔出 IB 光纤、断电或停止 storage。先从现场链路、配置与日志定位并修复，再从已有完整检查点恢复。诊断不会自动修复。
显存：调大 micro_batch_size 或 seq_length 可能 OOM，需要修改配置重新提交。
终端：输入 help 查看命令；终端与按钮访问同一份文件、服务和任务状态。

工程会自动存入当前浏览器。导出/导入可保存多个工程分支。关闭页面后工程时间冻结。

当前版本覆盖上述工程行为，仍是限定范围的工程仿真，不是完整 Linux/Python/CUDA，也不生成实际 70B 权重。训练与推理的行为系统使用当前工程数据和模型状态；不等于通用大语言模型。


v0.3 系统与集群
BMC 新增 Slurm 集群、服务进程和 GPU 资源页。先安装 Slurm，再分发 Munge 密钥、应用认证并启动节点代理，最后启动控制器。错误原因可在节点注册表和 journalctl 查看。
服务配置保存后，需 reload 或 restart 才生效。检查点分片写入完成后才允许恢复；中断或损坏版本会被跳过。
完整操作路径见 docs/系统与集群验收.md。
