MODEL FOUNDRY v0.8.0

打开 index.html 即可运行（源码仓库也提供 dist/index.html）。HTML 内已包含全部样式、脚本和 3D 场景，无外部依赖。

现场：WASD 移动，按住鼠标拖动观察，靠近并面向设备按 E。靠近电脑后 Tab 坐下，Esc 离座。界面按钮标记现场位置，不会将玩家直接传送到远处。

完整工程顺序：
1. 到各机柜前，打开机柜门，在接线页将 PDU 接至 PSU、管理网接至 eth0，计算节点还需将 IB 光纤接至 ib0。支持拖线或先后点击两端。
2. 硬件页上电、部署系统。网络页填写不重复的 10.42.0.10—15 地址，网关 10.42.0.1，DNS 10.42.0.10。保存后 netplan apply，再安装运行时。
3. 在 storage-01 的服务页安装 storage → 启动 → 挂载 /data。在 control-01 安装并启动 slurm、data、tracking、kubernetes 和 monitor。也可在工位终端执行 labctl install <service> / systemctl start <service>。
4. 坐到工位，Corpus Studio 接入项目语料或导入 JSONL。执行清洗 DAG，查看逐条输入输出与过滤原因，再编码构建训练分片。
5. Code 中检查配置并提交预训练。右上角可切到 12× 时间，MLflow 查看阶段耗时、Worker 与指标。终端可独立并排打开。
6. 数据工作区准备后训练集。Code 载入 SFT 配方、检查并提交；完成后再进行 DPO。
7. 模型仓库评测候选检查点，转换权重并注册。
8. 推理工作台发布模型，等待 READY，再对话与压力测试。Grafana 数据源连接后才采集指标。

故障：运行时可拔出 IB 光纤、断电或停止 storage。先从现场链路、配置与日志定位并修复，再从已有完整检查点恢复。诊断不会自动修复。
显存：调大 micro_batch_size 或 seq_length 可能 OOM，需要修改配置重新提交。
终端：输入 help 查看命令；终端与按钮访问同一份文件、服务和任务状态。

工程会自动存入当前浏览器。导出/导入可保存多个工程分支。关闭页面后工程时间冻结。

当前版本覆盖上述工程行为，仍是限定范围的工程仿真，不是完整 Linux/Python/CUDA，也不生成实际 70B 权重。训练与推理的行为系统使用当前工程数据和模型状态；不等于通用大语言模型。


v0.3 系统与集群
BMC 新增 Slurm 集群、服务进程和 GPU 资源页。先安装 Slurm，再分发 Munge 密钥、应用认证并启动节点代理，最后启动控制器。错误原因可在节点注册表和 journalctl 查看。
服务配置保存后，需 reload 或 restart 才生效。检查点分片写入完成后才允许恢复；中断或损坏版本会被跳过。
完整操作路径见 docs/系统与集群验收.md。


v0.4 完整执行链
数据平台包含记录审计、流水线、Packing、后训练样本与版本血缘。
Code 可编辑 project/recipe.py，检查会执行前向与 loss；错误对应具体行号。
训练页可扫描学习率；模型页逐样本评测，通过门槛后提交分片转换。
API 工作区支持真实请求队列、缓存、取消、压测、副本、灰度与回滚。
最大化软件窗口后，可在顶栏调整工程时间倍率。
完整工程存档可从“导入”打开；v0.4 使用 IndexedDB 保存大工程。
详细操作见 docs/执行与推理验收.md。


v0.5 可恢复的逐步执行
请求与 Trace 页新增暂停/恢复；暂停释放 KV，恢复先重建 KV。解码位置与 RNG 随工程保存。
评测计分与生成协议已更新，旧报告需要重新执行评测。驻留模型可以继续服务，新发布须通过当前协议。
新训练去掉阶段学习率倍率，未实现的框架接口明确报错。详见 docs/真实性基准与执行验收.md。


v0.6 逐 GPU 执行
新训练按物理 rank、micro batch 与通信依赖运行。MLflow 可查看逐卡、时间线、通信组、检查点和实验。
选中 rank 可限制其算力或定位机柜；断开物理 IB 后需修复连接，再从完整检查点恢复。
硬件配置位于 /etc/foundry/hardware.json，排空资源后应用。完整规则与假设见 docs/逐GPU执行与资源验收.md。
体验包“工程存档/逐GPU执行.json”可直接导入，继续后观察正在运行的 Atlas 70B 作业。


v0.7 Transformer 数值工程
新训练使用可微分的 Transformer。模型结构在 /workspace/atlas/model.json 中设置；提交前重新检查。后训练沿用父模型的结构和 Tokenizer。
训练页 → Transformer 内核：选择 Layer / Q Head，刷新真实注意力与梯度；完整检查点可下载 .safetensors 权重。
体验包内“工程存档/Transformer数值工程.json”为已建好环境并暂停的验收工程，导入后在训练页继续执行；也可从空机房自行建设。
机房资源按虚拟 Atlas 70B 表达，浏览器数值分配独立记录。默认数值结构为 2 层/32 hidden，不表示在浏览器训练了真实 70B 权重。详细流程、格式与边界见 docs/Transformer数值内核与验收.md。


v0.8 统一模型与操作语义
模型入口为 /workspace/atlas/model-spec.json，旧 model.json 作为 numeric 兼容入口。目标结构、数值参考结构与当前运行的冻结快照分别保留。
训练页 → 模型蓝图：选择 rank 检查每层张量、TP 区间、本地资源和不均匀检查点容量。
终端支持引号、变量、退出码、管道与重定向，squeue/sacct 支持明确的筛选与格式参数。foundryctl capabilities 查看固定场景清单统计。
体验包“工程存档/统一模型与终端工程.json”含已完成的 3 步训练和暂停时钟，可在 Code 修改配方重新检查提交。
当前固定 100 项场景内闭环 49 项、部分 34 项、未实现 17 项；49% 不表示真实性或全部工程工作量。详见 docs/工程场景完成度清单.md 和 docs/统一模型与操作语义验收.md。
